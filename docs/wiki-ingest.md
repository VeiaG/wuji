# Вікі-інжест: генерація вікі локальною моделлю

Скрипт `scripts/wikiIngest.ts` читає розділи книги, проганяє їх через локальну LLM (Ollama) і наповнює вікі-колекції:

- **Wiki Entries** — сутності (персонажі, локації, секти, техніки, предмети, царства, події, концепції)
- **Wiki Mentions** — докази: хто/що з'явилося в конкретному розділі, з цитатою і контекстом
- **Wiki Relations** — граф зв'язків між сутностями (учитель, ворог, член секти...)
- **Wiki Ingest Runs** — журнал прогонів (видно прогрес в адмінці, група "Вікі")

## Підготовка (один раз)

### 1. Встановити Ollama

Завантажити з <https://ollama.com/download> (Windows-інсталер). Після встановлення Ollama працює як сервіс на `http://localhost:11434`.

Перевірити, що працює:

```powershell
curl http://localhost:11434/api/tags
```

Якщо не відповідає — запустити вручну: `ollama serve`.

### 2. Спулити модель

Для RTX 3080 (10 GB VRAM) рекомендовано:

```powershell
ollama pull qwen3:8b        # ~5 GB, дефолт скрипта, добре тримає JSON і українську
```

Альтернативи:

```powershell
ollama pull qwen3:14b       # ~9 GB, розумніша, але впритул до ліміту VRAM — буде повільніша
ollama pull llama3.1:8b     # запасний варіант, якщо qwen3 не сподобається
```

Швидкий тест моделі:

```powershell
ollama run qwen3:8b "Привіт! Відповідай українською."
```

### 3. Залежності проєкту

Нічого додаткового: скрипт запускається через `tsx` (уже в devDependencies) і читає `.env` проєкту (база даних та ін.). Головне — щоб MongoDB була доступна, як для звичайного `pnpm dev`.

## Запуск

### Режим ingest (екстракція з розділів)

```powershell
pnpm wiki:ingest --slug <слаг-книги>
```

Приклади:

```powershell
# вся книга, дефолтна модель qwen3:8b
pnpm wiki:ingest --slug prynts-drakona-yuan

# перші 3 розділи — для перевірки якості перед повним прогоном
pnpm wiki:ingest --slug prynts-drakona-yuan --limit 3

# конкретний діапазон розділів іншою моделлю
pnpm wiki:ingest --slug prynts-drakona-yuan --from 10 --to 50 --model qwen3:14b
```

> **Порада:** перший раз запускайте з `--limit 3` і подивіться в адмінці, що модель наекстрагувала. Дешевше підкрутити промпт на трьох розділах, ніж на п'ятистах.

### Режим compose (генерація вікі-статей)

Коли назбиралися згадки, можна згенерувати самі статті (Markdown → Lexical):

```powershell
pnpm wiki:ingest --slug prynts-drakona-yuan --mode compose

# одна конкретна стаття
pnpm wiki:ingest --slug prynts-drakona-yuan --mode compose --entry van-lin
```

Compose бере записи зі статусом `auto`, у яких є щонайменше 2 згадки (`--min-mentions`), і пише статтю українською на основі накопичених доказів.

## Зупинка і продовження

- **Ctrl+C один раз** — скрипт докінчує поточний розділ і зупиняється.
- **Ctrl+C двічі** — виходить негайно; недороблений розділ просто буде перероблений наступним запуском.
- Прогрес зберігається у `wiki-ingest/<слаг>.json` (у git не потрапляє). Розділ позначається пройденим **лише після** повного збереження результатів, тому обрив у будь-який момент безпечний.
- Повторний запуск тієї ж команди продовжує з місця зупинки. Дублікатів не буде — всі записи йдуть через upsert поверх unique-індексів.
- Розділи, що впали з помилкою, не позначаються пройденими і повторяться самі наступного разу. 3 помилки поспіль = аварійна зупинка (найчастіше означає, що Ollama не запущена).

## Усі параметри

| Прапорець | Env-змінна | Дефолт | Опис |
|---|---|---|---|
| `--slug` | `WIKI_SLUG` | — (обов'язковий) | Слаг книги |
| `--mode` | `WIKI_MODE` | `ingest` | `ingest` або `compose` |
| `--from` | `WIKI_FROM` | `1` | Перший розділ діапазону (нумерація як в URL читалки) |
| `--to` | `WIKI_TO` | останній | Останній розділ діапазону |
| `--limit` | `WIKI_LIMIT` | без ліміту | Максимум розділів за один запуск |
| `--model` | `WIKI_MODEL` | `qwen3:8b` | Модель Ollama |
| `--ollama` | `OLLAMA_URL` | `http://localhost:11434` | Адреса Ollama |
| `--ctx` | `WIKI_NUM_CTX` | `16384` | Контекстне вікно (num_ctx) |
| `--temperature` | `WIKI_TEMPERATURE` | `0.2` | Температура генерації |
| `--min-mentions` | `WIKI_MIN_MENTIONS` | `2` | (compose) мінімум згадок для статті |
| `--entry` | `WIKI_ENTRY` | — | (compose) слаг одного запису |
| `--force` | — | — | Переобробити вже пройдені розділи / перегенерувати статті |

## Правила, які скрипт гарантує

- ШІ **ніколи не перезаписує** записи, яких торкалася людина: оновлюються лише записи зі статусом `auto`. Відредагували запис — поставте йому `review` або `published`, і пайплайн його не чіпатиме (згадки при цьому додаватимуться далі).
- Номери розділів скрізь 1-базовані — ті самі, що в URL (`/novel/slug/N`) і в `readProgress.chapter`. Спойлер-фільтрація на фронтенді: `spoilerChapterIndex <= прогрес читача`.
- Симетричні зв'язки (друг, ворог, суперник...) зберігаються в одному напрямку, тож дублікатів A→B / B→A не буде.

## Типові проблеми

| Симптом | Причина / рішення |
|---|---|
| `LLM attempt 1/3 failed: fetch failed` | Ollama не запущена → `ollama serve` або перевірити службу |
| `Ollama HTTP 404: model not found` | Модель не спулена → `ollama pull qwen3:8b` |
| Дуже повільно, GPU не завантажений | Модель не влізла у VRAM і працює на CPU → менша модель або менший `--ctx` |
| Модель плодить дублікати сутностей з різним написанням | Нормально для малих моделей; злийте записи вручну в адмінці (аліаси!) і наступні прогони підхоплять правильну назву |
| `Книгу зі слагом "..." не знайдено` | Перевірте слаг на сторінці книги в адмінці |
| Обробка почалася з початку, хоча вже щось оброблялося | Видалений/змінений `wiki-ingest/<слаг>.json` або книга була переімпортована з новим id |

## Після інжесту

1. Переглянути записи в адмінці (група **Вікі**), виправити типи/назви, злити дублікати.
2. Запустити `--mode compose` для генерації статей.
3. Вичитані статті переводити в статус `published` — тоді ШІ їх більше не перепише.

## Вікі на сайті

Щойно у книги з'являється хоч один запис зі статусом `auto` або `published`, на її сторінці автоматично з'являється кнопка **Вікі (бета)**, а сама вікі доступна за адресою `/novel/<слаг>/wiki`:

- **`/novel/<слаг>/wiki`** — каталог записів із пошуком і фільтром за типом.
- **`/novel/<слаг>/wiki/<слаг-запису>`** — стаття: опис, зв'язки з іншими записами, згадки за розділами з цитатами.
- Спойлери фільтруються за збереженим прогресом читання (`spoilerChapterIndex <= прогрес`); все, що далі — приховано, з кнопкою «Показати спойлери» (`?spoilers=1`). Анонімні читачі без прогресу бачать лише записи без прив'язки до розділу, поки не увімкнуть спойлери.
- Записи зі статусами `review` та `hidden` на сайті не показуються взагалі.
- Поки вікі в беті, сторінки мають `noindex` і не потраплять у пошуковики.
